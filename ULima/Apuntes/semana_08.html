Módulo 1: Resumen Estratégico de Alto Rendimiento (Semanas 01 a 07)

S01-S02: Arquitectura ANSI-SPARC & ACID

3 Niveles: Externo (Vistas de usuario), Conceptual (Lógico/Tablas independiente del DBMS), Interno (Físico/B-Trees/Almacenamiento). ACID garantiza transacciones confiables.

S03: Integridad Relacional

1. Dominio (tipos válidos), 2. Entidad (PK NOT NULL y UNIQUE), 3. Referencial (FK debe apuntar a PK existente o ser NULL).

S04-S05: DDL, DML & MVCC

DDL: CREATE/ALTER/DROP. DML: INSERT/UPDATE/DELETE. Postgres usa MVCC (xmin, xmax, dead tuples). WHERE evalúa a 3VL (TRUE, FALSE, UNKNOWN).

S06-S07: DER & Normalización

Entidades Débiles (PK padre + discriminador), Jerarquías (Disjunta/Solapada x Total/Parcial). 1FN (Atomicidad), 2FN (Cero dep. parciales), 3FN (Cero dep. transitivas), BCNF (Determinante es superclave).

Módulo 2: Top 10 Trampas Clásicas de Examen y Cómo Neutralizarlas

❌ Trampa 1: WHERE columna = NULL Neutralización: En SQL, NULL = NULL da UNKNOWN y nunca retorna filas. Utilice siempre IS NULL o IS NOT NULL.
❌ Trampa 2: Asumir que una clave simple garantiza 3FN Neutralización: Una clave simple garantiza automáticamente 2FN (porque no pueden existir dependencias parciales), pero NO 3FN (puede haber dependencias transitivas entre atributos no primos $A \to B$).
❌ Trampa 3: COUNT(*) vs COUNT(columna) Neutralización: COUNT(*) cuenta todas las filas incluyendo las que tienen valores nulos. COUNT(columna) ignora las filas donde dicha columna es NULL.
❌ Trampa 4: Confundir DELETE con TRUNCATE en el examen Neutralización: DELETE es DML, borra fila a fila, permite WHERE y dispara triggers. TRUNCATE es DDL, desasigna páginas de almacenamiento y no admite WHERE.
❌ Trampa 5: Mapear atributos multivaluados como columnas repetidas (tel1, tel2) Neutralización: Violaría 1FN. Un atributo multivaluado siempre se mapea a una tabla independiente con la PK del padre como FK.

Módulo 3: Banco de 5 Preguntas Teóricas Tipo Examen

❓ P1: ¿Por qué una relación en 3FN podría no estar en BCNF? Ver Solución

Respuesta Maestra (20/20): Porque la definición de 3FN permite que en una dependencia $X \to Y$, $X$ no sea superclave siempre y cuando $Y$ sea un atributo primo (pertenezca a alguna clave candidata). Si una relación tiene múltiples claves candidatas compuestas que se superponen, puede satisfacer 3FN pero violar BCNF.

❓ P2: ¿Cuál es la diferencia formal entre Independencia Lógica y Física de Datos? Ver Solución

Respuesta Maestra: La Independencia Física permite modificar las estructuras de almacenamiento físico (ej. crear un índice B-Tree o particionar una tabla) sin alterar el esquema conceptual ni las consultas de las aplicaciones. La Independencia Lógica permite mutar el esquema conceptual (añadir atributos o entidades) sin alterar las vistas externas ni romper los programas de usuario existentes.

Módulo 4: Los 4 Grandes Ejercicios Prácticos Resueltos Paso a Paso

Ejercicio 1 (5 Ptos): Modelamiento E-R y Mapeo Relacional Completo

Caso Empresarial

Caso: Una cadena logística necesita gestionar Flotas de Transporte, Conductores, Rutas y Paquetes. Un Conductor puede ser Propio (con sueldo fijo) o Tercerizado (con tarifa por km). Cada Paquete tiene un historial de Estados de Envío (Entidad Débil).

DIAGRAMA DER ASCII (NOTACIÓN CHEN / EER) ======================================================================================== [CONDUCTOR] (Supertipo) | (d,=) (Disjunta Total: Todo conductor es Propio O Tercerizado) / \ [COND_PROPIO] [COND_TERCERIZADO] - sueldo_fijo - tarifa_km [CONDUCTOR] ----- (1,N) ----- ----- (1,1) ----- [VEHICULO] | (1,N) | | (1,1) [PAQUETE] ====== ====== [[ESTADO_ENVIO]] (Identificadora) (Débil) ========================================================================================

Esquema Relacional PostgreSQL 16 DDL Generado:

-- Supertipo CREATE TABLE conductor ( id_conductor INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY, dni VARCHAR(8) NOT NULL UNIQUE, nombres VARCHAR(100) NOT NULL, tipo_conductor CHAR(1) NOT NULL CHECK (tipo_conductor IN ('P', 'T')) ); -- Subtipos (Class Table Inheritance) CREATE TABLE cond_propio ( id_conductor INTEGER PRIMARY KEY REFERENCES conductor(id_conductor) ON DELETE CASCADE, sueldo_fijo NUMERIC(10,2) NOT NULL CHECK (sueldo_fijo > 0) ); CREATE TABLE cond_tercerizado ( id_conductor INTEGER PRIMARY KEY REFERENCES conductor(id_conductor) ON DELETE CASCADE, tarifa_km NUMERIC(6,2) NOT NULL CHECK (tarifa_km > 0) ); -- Entidad Fuerte y Débil CREATE TABLE paquete ( id_paquete INTEGER PRIMARY KEY GENERATED ALWAYS AS IDENTITY, codigo_tracking VARCHAR(30) NOT NULL UNIQUE, peso_kg NUMERIC(6,2) NOT NULL CHECK (peso_kg > 0) ); CREATE TABLE estado_envio ( id_paquete INTEGER NOT NULL REFERENCES paquete(id_paquete) ON DELETE CASCADE, num_secuencia SMALLINT NOT NULL, ubicacion VARCHAR(100) NOT NULL, fecha_hora TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, PRIMARY KEY (id_paquete, num_secuencia) );

Ejercicio 2 (5 Ptos): Normalización Matemática Rigurosa (0FN a 3FN/BCNF)

Demostración Formal
Sea R(A, B, C, D, E, G) con el conjunto de DFs F: DF1: A, B -> C, D, E DF2: B -> D DF3: D -> E DF4: C -> G 1. Cierre de Atributos y Clave Primaria: (A, B)+ = {A, B, C, D, E, G} = R. Clave Candidata Universal: (A, B). Atributos Primos: {A, B}. Atributos No Primos: {C, D, E, G}. 2. Paso a 2FN (Eliminar dependencia parcial DF2: B -> D): - R1(B, D) [DF2: B -> D] - R2(A, B, C, E, G) [DF1 restante, DF3, DF4] 3. Paso a 3FN (Eliminar dependencias transitivas DF3: D -> E y DF4: C -> G): - De R1 con D -> E: * TABLA_B(B, D*) (D es FK a TABLA_D) * TABLA_D(D, E) - De R2 con C -> G: * TABLA_C(C, G) * TABLA_AB(A, B, C*) (C es FK a TABLA_C) Resultado Final en 3FN y BCNF: TABLA_D(D, E) TABLA_B(B, D) TABLA_C(C, G) TABLA_AB(A, B, C)

Ejercicio 3 & 4 (10 Ptos): SQL Avanzado, Filtros WHERE, Lógica 3VL y TCL

SQL & TCL
-- Consulta con Filtros Complejos, Distinct On y Lógica Trivaluada SELECT DISTINCT ON (c.id_cliente) c.id_cliente, c.nombres, o.numero_orden, o.fecha_colocacion, COALESCE(o.numero_embarques, 0) AS total_embarques FROM cliente c JOIN orden_pedido o ON c.id_cliente = o.id_cliente WHERE (o.fecha_llenado IS NOT NULL OR o.numero_embarques >= 2) AND c.tipo IN ('A', 'B') ORDER BY c.id_cliente, o.fecha_colocacion DESC NULLS LAST; -- Flujo Transaccional Seguro con SAVEPOINT BEGIN; INSERT INTO cliente (dni, nombres, tipo_conductor) VALUES ('72819201', 'Luis Torres', 'P'); SAVEPOINT sp1; UPDATE producto SET stock = stock - 10 WHERE id_producto = 101 AND stock >= 10; -- Si falla la verificación de saldo: -- ROLLBACK TO SAVEPOINT sp1; COMMIT;

Módulo 5: Rúbrica Oficial de Evaluación (Nota 20)

Criterio / Competencia Excelente (5 Pts) Regular (2.5 Pts) Deficiente (0 Pts)
1. Fundamentos & Teoría Justifica formalmente con axiomas, niveles ANSI-SPARC y evita todas las trampas de NULLs. Responde conceptualmente pero omite justificación matemática. Confunde sublenguajes o comete errores de lógica trivaluada.
2. Normalización Matemática Calcula cierres X+, identifica atributos primos y descompone sin pérdida hasta 3FN/BCNF. Descompone a 3FN pero comete errores en dependencias parciales. No demuestra el cálculo del cierre de atributos.
3. Modelamiento E-R Identifica entidades débiles, asociativas y mapea supertipos a Class Table con PK/FK 1:1. Modela cardinalidades pero confunde participación obligatoria/opcional. Omite entidades débiles y comete errores en relaciones M:N.
4. SQL DDL / DML / TCL Escribe SQL PostgreSQL 16 sin errores, con constraints CHECK, RETURNING y SAVEPOINTs. Sintaxis SQL funcional pero con errores menores de tipos de datos. Sentencias DDL inválidas o que violan integridad referencial.
