⚡ Arquitectura MVCC & ACID

Control de concurrencia multiversión mediante tuplas con encabezados xmin / xmax sin bloqueos de lectura.

⚡ Arquitectura Interna: MVCC, Tuplas Muertas y Table Bloat en PostgreSQL 16/17

A diferencia de otros motores que usan cerrojos pesados o segmentos de rollback separados para deshacer cambios, PostgreSQL implementa el modelo MVCC (Multi-Version Concurrency Control) mediante encabezados de tupla que contienen los identificadores de transacción xmin (creador) y xmax (eliminador o actualizador).

INSERT Crea una nueva tupla con xmin = TX_ACTUAL y xmax = 0. La tupla es visible de inmediato para las lecturas posteriores dentro del mismo snapshot.
UPDATE No sobreescribe la fila en disco. Ejecuta un DELETE lógico marcando la tupla actual con xmax = TX_ACTUAL e inserta una nueva tupla con xmin = TX_ACTUAL.
DELETE No borra los bytes físicamente al instante; establece el xmax de la tupla con el ID de la transacción que la eliminó. Pasa a ser una dead tuple recuperable por VACUUM.

1. Clasificación Formal de los Sublenguajes SQL

El estándar ANSI/ISO SQL estructura las operaciones de bases de datos en cuatro categorías funcionales fundamentales:

Sublenguaje Propósito Comandos Principales Comportamiento Transaccional
DML (Data Manipulation) Inserción, modificación, eliminación y consulta de tuplas de datos. INSERT, UPDATE, DELETE, SELECT, MERGE Totalmente transaccional. Requiere COMMIT para persistir.
DDL (Data Definition) Definición y alteración de esquemas, tablas, tipos e índices. CREATE, ALTER, DROP, TRUNCATE, RENAME En Oracle hace autocommit; en PostgreSQL es transaccional.
DCL (Data Control) Gestión de privilegios, roles y permisos de seguridad. GRANT, REVOKE Afecta inmediatamente el catálogo del sistema.
TCL (Transaction Control) Control de fronteras y atomicidad de las transacciones. COMMIT, ROLLBACK, SAVEPOINT, SET TRANSACTION Determina el destino final de las mutaciones DML.

2. Inserción, Modificación y Eliminación de Datos (DML)

2.1 INSERT INTO: Inserción Básica, Múltiple y con Cláusula RETURNING

La sentencia INSERT añade una o más filas a una tabla. Si no se especifican las columnas, se deben proporcionar valores para todos los atributos en el orden exacto de definición de la tabla.

-- 1. Inserción posicional completa INSERT INTO cliente VALUES (101, 'Corporación Andina S.A.C.', 'Av. Javier Prado 4500', 'A', '15023'); -- 2. Inserción con lista explícita de columnas (Mejor práctica recomendada) INSERT INTO producto (id_producto, nombre_linea, stock, precio, costo) VALUES (5001, 'Muebles Oficina', 25, 450.00, 280.00); -- 3. Inserción múltiple (Bulk Insert atómico estándar ANSI) INSERT INTO linea_producto (nombre_linea) VALUES ('Muebles Oficina'), ('Hogar y Comedor'), ('Dormitorio Moderno'); -- 4. PostgreSQL Feature: Cláusula RETURNING para evitar consultas adicionales INSERT INTO orden_pedido (fecha_colocacion, numero_embarques, id_cliente) VALUES (CURRENT_DATE, 1, 101) RETURNING numero_orden, fecha_colocacion, id_cliente; -- 5. Manejo de Conflictos: UPSERT (INSERT ... ON CONFLICT DO UPDATE) INSERT INTO producto (id_producto, nombre_linea, stock, precio, costo) VALUES (5001, 'Muebles Oficina', 30, 470.00, 290.00) ON CONFLICT (id_producto) DO UPDATE SET stock = EXCLUDED.stock, precio = EXCLUDED.precio, costo = EXCLUDED.costo;

2.2 UPDATE: Modificación Condicional y Actualización con Joins

UPDATE modifica los valores de las columnas existentes. Regla de oro: Toda sentencia UPDATE en entornos operacionales debe llevar una cláusula WHERE explícita, a menos que intencionalmente se desee actualizar la totalidad de la tabla.

-- 1. Actualización simple con condición matemática UPDATE producto SET precio = precio * 1.08, costo = costo * 1.05 WHERE nombre_linea = 'Muebles Oficina' AND stock > 10; -- 2. Actualización basada en subconsulta UPDATE cliente SET tipo = 'A' WHERE id_cliente IN ( SELECT id_cliente FROM orden_pedido GROUP BY id_cliente HAVING COUNT(numero_orden) >= 5 ); -- 3. UPDATE con JOIN utilizando la cláusula FROM (PostgreSQL Syntax) UPDATE producto p SET meta_venta = p.meta_venta * 1.15 FROM linea_producto lp WHERE p.nombre_linea = lp.nombre_linea AND lp.nombre_linea = 'Dormitorio Moderno' RETURNING p.id_producto, p.nombre_linea, p.meta_venta;

3. Recuperación de Datos con SELECT

La sentencia SELECT implementa los operadores fundamentales del álgebra relacional: la Proyección ($\pi$) para seleccionar columnas y la Selección ($\sigma$) para filtrar tuplas que cumplan un predicado lógico.

-- Proyección con alias, cálculos aritméticos y funciones escalares SELECT id_producto, nombre_linea, precio, costo, (precio - costo) AS margen_bruto, ROUND(((precio - costo) / precio) * 100, 2) AS porcentaje_margen, UPPER(nombre_linea) AS linea_mayuscula, COALESCE(stock, 0) AS stock_disponible FROM producto;

4. Filtrado WHERE y la Lógica Trivaluada (Three-Valued Logic)

En SQL, el valor especial NULL representa la ausencia de dato o un valor desconocido. Por tanto, SQL no opera con lógica booleana binaria (Verdadero/Falso), sino con una Lógica Trivaluada (3VL) compuesta por TRUE, FALSE y UNKNOWN.

* REGLA DE ORO DE WHERE: La cláusula WHERE solo retorna filas cuyo predicado evalúe estrictamente a TRUE. Si evalúa a FALSE o UNKNOWN, la fila se DESCARTA.

⚠️ Trampa Clásica de Examen: Comparaciones con NULL

La expresión WHERE fecha_llenado = NULL nunca retornará ninguna fila porque NULL = NULL evalúa a UNKNOWN, no a TRUE.

-- INCORRECTO (Retorna 0 filas siempre):
SELECT * FROM orden_pedido WHERE fecha_llenado = NULL;

-- CORRECTO (Sintaxis estándar ANSI):
SELECT * FROM orden_pedido WHERE fecha_llenado IS NULL;
SELECT * FROM orden_pedido WHERE fecha_llenado IS NOT NULL;

4.1 Operadores Especiales de Predicado

-- 1. Operador BETWEEN ... AND (Inclusivo en ambos límites) SELECT numero_orden, fecha_colocacion, id_cliente FROM orden_pedido WHERE fecha_colocacion BETWEEN '2026-01-01' AND '2026-06-30'; -- 2. Operador IN (Lista explícita o subconsulta) SELECT id_cliente, nombre, tipo, zip FROM cliente WHERE tipo IN ('A', 'B') AND zip IN ('15023', '15024', '15036'); -- 3. Operadores de Coincidencia de Patrones: LIKE e ILIKE -- %: Coincide con 0 o más caracteres -- _: Coincide con exactamente un carácter SELECT id_cliente, nombre, direccion FROM cliente WHERE nombre LIKE 'Corp%' -- Case-sensitive AND direccion ILIKE '%av.%'; -- PostgreSQL Case-insensitive

5. Ordenamiento (ORDER BY) y Paginación Determinista

Por definición matemática del modelo relacional, las tuplas en una tabla no tienen un orden inherente. La única forma de garantizar un orden de presentación consiste en utilizar ORDER BY.

-- 1. Ordenamiento múltiple con control explícito de nulos SELECT numero_orden, fecha_colocacion, fecha_llenado, id_cliente FROM orden_pedido ORDER BY fecha_colocacion DESC, fecha_llenado ASC NULLS LAST; -- 2. Eliminación de Duplicados: DISTINCT vs DISTINCT ON (PostgreSQL) SELECT DISTINCT nombre_linea FROM producto; -- DISTINCT ON: Retorna la primera fila para cada grupo según el ORDER BY SELECT DISTINCT ON (id_cliente) id_cliente, numero_orden, fecha_colocacion FROM orden_pedido ORDER BY id_cliente, fecha_colocacion DESC; -- 3. Paginación Determinista en APIs y Microservicios (LIMIT & OFFSET) SELECT id_producto, nombre_linea, precio FROM producto ORDER BY id_producto ASC LIMIT 10 OFFSET 20; -- Retorna la página 3 (filas 21 a 30)

6. Control de Transacciones DML (ACID y SAVEPOINTS)

Una transacción es una unidad lógica de trabajo indivisible. En aplicaciones bancarias o de comercio electrónico, los SAVEPOINTS permiten establecer puntos de restauración intermedios para revertir errores parciales sin cancelar la totalidad del flujo transaccional.

-- Inicio explícito de la transacción BEGIN; -- Paso 1: Insertar la cabecera de la orden INSERT INTO orden_pedido (numero_orden, fecha_colocacion, numero_embarques, id_cliente) VALUES (99001, CURRENT_DATE, 1, 101); -- Paso 2: Crear un punto de restauración intermedio SAVEPOINT punto_lineas_pedido; -- Paso 3: Descontar stock del producto ordenado UPDATE producto SET stock = stock - 5 WHERE id_producto = 5001 AND stock >= 5; -- Paso 4: Supongamos que ocurre un error al intentar insertar un producto inexistente -- En lugar de abortar toda la compra, revertimos al SAVEPOINT: ROLLBACK TO SAVEPOINT punto_lineas_pedido; -- Paso 5: Proceder con un producto alternativo válido UPDATE producto SET stock = stock - 2 WHERE id_producto = 5002 AND stock >= 2; -- Confirmar permanentemente todos los cambios válidos COMMIT;

7. Ejercicios Prácticos de Laboratorio Resueltos

📝 Ejercicio 1: Actualización Masiva con Cláusula CASE y RETURNING Resuelto

Enunciado: Incremente el precio de los productos de la línea 'Muebles Oficina' en un 12% si su stock es menor a 15 unidades, y en un 5% en caso contrario. La consulta debe devolver el ID, nuevo precio y monto del incremento.

UPDATE producto
SET precio = CASE 
    WHEN stock < 15 THEN ROUND(precio * 1.12, 2)
    ELSE ROUND(precio * 1.05, 2)
END
WHERE nombre_linea = 'Muebles Oficina'
RETURNING id_producto, precio AS nuevo_precio, stock;
📝 Ejercicio 2: Búsqueda con Lógica Trivaluada y Filtros Combinados Resuelto

Enunciado: Liste todas las órdenes de pedido cuyo número de embarques sea mayor a 1 o nulo, pero que pertenezcan a clientes de tipo 'A' o 'C' y cuya fecha de colocación sea posterior al 1 de enero de 2026.

SELECT o.numero_orden, o.fecha_colocacion, o.numero_embarques, o.id_cliente
FROM orden_pedido o
JOIN cliente c ON o.id_cliente = c.id_cliente
WHERE (o.numero_embarques > 1 OR o.numero_embarques IS NULL)
  AND c.tipo IN ('A', 'C')
  AND o.fecha_colocacion > '2026-01-01'
ORDER BY o.fecha_colocacion DESC, o.numero_orden ASC;
