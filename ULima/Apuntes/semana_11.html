1. Agrupamiento Multidimensional: ROLLUP, CUBE y GROUPING SETS

En SQL estándar y en motores analíticos modernos, calcular totales y subtotales en múltiples niveles solía requerir múltiples consultas unidas con `UNION ALL`. Las extensiones de agrupamiento multidimensional resuelven esto en un solo escaneo eficiente de tabla.

GROUPING SETS

Permite especificar explícitamente qué combinaciones de agrupamiento deben calcularse, omitiendo agrupaciones innecesarias. 

GROUP BY GROUPING SETS (
  (pais, anio),
  (pais),
  ()
)

ROLLUP (Jerárquico)

Genera subtotales acumulativos progresivos de derecha a izquierda. Ideal para dimensiones jerárquicas (Año > Mes > Día). 

GROUP BY ROLLUP (
  anio, mes, dia
)
-- N+1 agrupaciones

CUBE (Combinatorio)

Calcula todas las combinaciones posibles ($2^N$ agrupaciones). Ideal para análisis exploratorio multidimensional cruzado. 

GROUP BY CUBE (
  pais, producto
)
-- 2^2 = 4 agrupaciones
-- Consulta ROLLUP con Identificación de Subtotales mediante GROUPING()
SELECT 
    COALESCE(pais, '** TOTAL GLOBAL **') AS pais,
    CASE WHEN GROUPING(categoria) = 1 THEN '** Subtotal País **' ELSE categoria END AS categoria,
    SUM(monto_venta) AS total_ventas,
    COUNT(orden_id) AS cantidad_transacciones
FROM ventas
GROUP BY ROLLUP(pais, categoria)
ORDER BY pais, GROUPING(categoria), categoria;

2. Funciones de Ventana Analíticas (Window Functions)

Las funciones de ventana realizan cálculos sobre un conjunto de tuplas relacionadas con la tupla actual (llamado marco de ventana o frame). A diferencia de `GROUP BY`, las filas individuales no se comprimen en una sola fila.

/* ANATOMÍA DE LA CLÁUSULA OVER EN SQL:2026 */
FUNCTION_NAME(expr) OVER (
    [PARTITION BY col1, col2, ...]      <-- Divide el dataset en islas independientes
    [ORDER BY sort_col [ASC|DESC], ...] <-- Define la secuencia temporal/lógica
    [ROWS|RANGE BETWEEN frame_start AND frame_end] <-- Delimita el horizonte de tuplas
)

FRAME SPECIFICATIONS:
  - UNBOUNDED PRECEDING : Desde la primera tupla de la partición.
  - n PRECEDING         : n tuplas anteriores a la fila actual.
  - CURRENT ROW         : La fila actual que se está evaluando.
  - n FOLLOWING         : n tuplas posteriores a la fila actual.
  - UNBOUNDED FOLLOWING : Hasta la última tupla de la partición.

Diferencia Crítica de Ranking: ROW_NUMBER vs RANK vs DENSE_RANK

Patrones Analíticos de Producción: Running Totals y Medias Móviles

-- Media Móvil de 3 Días y Total Acumulado en PostgreSQL 16/17
SELECT 
    fecha_transaccion,
    monto,
    -- Total Acumulado por Cliente (Running Total)
    SUM(monto) OVER (
        PARTITION BY cliente_id 
        ORDER BY fecha_transaccion
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS total_acumulado,
    -- Media Móvil Centrada de 3 Días (Día anterior + Actual + Día siguiente)
    AVG(monto) OVER (
        PARTITION BY cliente_id 
        ORDER BY fecha_transaccion
        ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
    ) AS media_movil_3d,
    -- Crecimiento Porcentual respecto al periodo anterior (MoM)
    ROUND(
        ((monto - LAG(monto, 1) OVER (PARTITION BY cliente_id ORDER BY fecha_transaccion)) 
         / NULLIF(LAG(monto, 1) OVER (PARTITION BY cliente_id ORDER BY fecha_transaccion), 0)) * 100, 
        2
    ) AS crecimiento_pct_mom
FROM transacciones;

3. Common Table Expressions (CTEs) y Algoritmo de Recursión

Una CTE (Common Table Expression) define un conjunto de resultados temporal accesible dentro del alcance de ejecución de una sola sentencia `SELECT`, `INSERT`, `UPDATE` o `DELETE`.

/* Diagrama: Algoritmo de Evaluación de WITH RECURSIVE */
PASO 1: Evaluar Anchor Member (Miembro Ancla)

└── Cargar tuplas base en la Tabla de Trabajo (Working Table) e Insertar en el Resultado Final.

PASO 2: Bucle de Recursión (Mientras Working Table no esté vacía)
  • ├── Evaluar Recursive Member usando las tuplas de Working Table.
  • ├── Cargar nuevas tuplas hijas en Intermediate Table.
  • ├── Reemplazar Working Table con Intermediate Table.
  • └── Agregar nuevas tuplas al Resultado Final (UNION ALL).
PASO 3: Retornar el Resultado Final acumulado.

Caso de Estudio: Explosión de Jerarquías Corporativas (Organigrama)

-- CTE Recursiva con Cálculo de Nivel, Ruta Completa y Detección de Ciclos en PG 16/17
WITH RECURSIVE organigrama AS (
    -- 1. ANCHOR MEMBER: El CEO / Nodo Raíz (jefe_id IS NULL)
    SELECT 
        emp_id,
        nombre,
        jefe_id,
        1 AS nivel,
        ARRAY[emp_id] AS ruta_jerarquica,
        nombre::TEXT AS ruta_nombres
    FROM empleados
    WHERE jefe_id IS NULL

    UNION ALL

    -- 2. RECURSIVE MEMBER: Empleados que reportan a la tanda anterior
    SELECT 
        e.emp_id,
        e.nombre,
        e.jefe_id,
        o.nivel + 1,
        o.ruta_jerarquica || e.emp_id,
        o.ruta_nombres || ' -> ' || e.nombre
    FROM empleados e
    JOIN organigrama o ON e.jefe_id = o.emp_id
    -- Salvaguarda: Evitar bucles infinitos en grafos con ciclos
    WHERE NOT (e.emp_id = ANY(o.ruta_jerarquica))
)
SELECT 
    REPEAT('  └── ', nivel - 1) || nombre AS jerarquia_visual,
    nivel,
    ruta_nombres
FROM organigrama
ORDER BY ruta_jerarquica;

🏛️ Arquitecto de Datos

Preservación de Granularidad Atómica y Métricas Multidimensionales

A diferencia del colapso de tuplas que impone GROUP BY, las Window Functions calculan agregaciones acumuladas (YTD/MTD), medias móviles y análisis de cohortes preservando intacta la granularidad atómica de cada transacción individual. En la metodología de Ralph Kimball, esto evita la creación desordenada de tablas intermedias preagregadas, permitiendo que la capa de visualización acceda a hechos atómicos contextualizados por métricas relativas.

📖 Referencia: Ralph Kimball & Margy Ross — The Data Warehouse Toolkit (3rd Ed.), Cap. 1: Dimensional Modeling & Metrics Integrity
⚙️ Ingeniero de Datos

El Nodo WindowAgg y el Coste Oculto de Frames: ROWS vs. RANGE

Internamente, el optimizador traduce el OVER() a un nodo WindowAgg antecedido por un Sort. Usar RANGE BETWEEN por omisión fuerza al motor a comparar valores lógicos entre filas adyacentes para detectar pares (peers), con alto overhead de CPU. Especificar ROWS BETWEEN permite acceder directamente por desplazamiento físico de memoria en buffer lineal. Respaldar las cláusulas con índices B-Tree compuestos (partición + orden) previene el paso de ordenación en disco.

📖 Referencia: Documentación Oficial PostgreSQL & Internals: Window Function Processing & WindowAgg Execution Node
☁️ Ingeniero Cloud & MDS

Micro-Partitioning, Clustering y Mitigación de Skew en Nube

En almacenes analíticos cloud como Snowflake o BigQuery, calcular ventanas sobre columnas con alta asimetría de valores (Data Skew) satura la memoria de un único nodo del clúster, provocando desbordamiento a almacenamiento remoto (Remote Disk Spilling) y disparando los costos FinOps de cómputo. El Ingeniero Cloud define llaves de clustering que agrupan los micro-bloques en el almacenamiento columnar alineados a la partición de la ventana para máxima eficiencia.
