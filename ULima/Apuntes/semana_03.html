01. Fundamentos Matemáticos del Modelo Relacional (E. F. Codd)

Publicado en junio de 1970 por Edgar Frank Codd en su célebre artículo "A Relational Model of Data for Large Shared Data Banks", el modelo relacional se fundamenta rigurosamente en la teoría matemática de conjuntos y la lógica de predicados de primer orden.

Definición Formal de Relación Matemática

Dados $n$ dominios $D_1, D_2, dots, D_n$ (conjuntos de valores atómicos), una relación $R$ definida sobre dichos dominios es un subconjunto del producto cartesiano:

R ⊆ D1 × D2 × … × Dn

Cada elemento $t in R$ es una tupla (una $n$-upla ordenada $(v_1, v_2, dots, v_n)$ donde cada $v_i in D_i$).

Término Teórico Formal (Codd) Término Estándar SQL Término Coloquial de Archivos Definición Operativa
Relación (Relation) Tabla (Table) Archivo (File) Estructura bidimensional compuesta por tuplas y atributos definidos.
Tupla (Tuple) Fila (Row) Registro (Record) Instancia individual de datos que representa una entidad concreta.
Atributo (Attribute) Columna (Column) Campo (Field) Propiedad con nombre y dominio tipado que describe la relación.
Grado (Arity / Degree) Número de Columnas Ancho de Registro Cantidad total de atributos en el esquema de la relación.
Cardinalidad Número de Filas Total de Registros Cantidad actual de tuplas persistidas en la relación.

Las 4 Propiedades Axiomáticas de las Relaciones

1. No existen tuplas duplicadas

Por definición de conjunto matemático, ningún elemento se repite. Toda relación debe tener una clave primaria (PK) única.

2. El orden de las filas es irrelevante

Las tuplas no tienen un ordenamiento intrínseco. Si se requiere ordenación visual, debe solicitarse explícitamente mediante ORDER BY.

3. El orden de las columnas es irrelevante

Los atributos se identifican estrictamente por su nombre simbólico y no por su posición física ordinal (eliminando offsets fijos).

4. Atomicidad de los Valores (1NF)

Cada intersección de fila y columna contiene exactamente un único valor indivisible del dominio (prohibidos arreglos anidados sin tipo formal).

02. Teoría de Claves y Restricciones de Integridad

El motor relacional preserva la exactitud y veracidad de la información mediante la ejecución estricta de restricciones declarativas.

Jerarquía Conceptual de Claves Relacionales
SUPERCLAVE (Superkey)

Cualquier subconjunto de atributos {A1, A2, ...} que identifica unívocamente a cada tupla en la relación. (Ej: {DNI, Email, Nombre, Teléfono})

CLAVE CANDIDATA (Candidate Key)

Una superclave MINIMAL (sin atributos redundantes). (Ej: {DNI} es candidata; {Email} es candidata)

CLAVE PRIMARIA (Primary Key)

Elegida formalmente por el arquitecto como identificador. (Restricción: NOT NULL UNIQUE)

CLAVE ALTERNATIVA

Las demás claves candidatas no elegidas. (Restricción: UNIQUE)

🔗 Acciones de Mantenimiento de Integridad Referencial (ON DELETE / ON UPDATE)

Cuando una tupla en la tabla Padre es eliminada o actualizada, el motor aplica la regla referencial configurada sobre las tablas Hijas:

ON DELETE RESTRICT

Rechaza inmediatamente la eliminación del padre si existe al menos una tupla hija asociada, lanzando un error de integridad.

ON DELETE NO ACTION (Default)

Comportamiento estándar SQL; valida las restricciones al final de la sentencia o transacción (permite restricciones diferidas DEFERRABLE).

ON DELETE CASCADE

Elimina automáticamente todas las tuplas hijas dependientes cuando el registro padre es eliminado.

ON DELETE SET NULL

Asigna automáticamente el valor NULL a la columna FK en las tuplas hijas (requiere que la columna sea anulable).

03. Sistema de Tipos de Datos ANSI SQL y PostgreSQL 16/17

Seleccionar el tipo de dato óptimo es crítico para minimizar el espacio en disco, maximizar la eficiencia del Buffer Pool y garantizar la exactitud de los cálculos aritméticos.

Familia Tipo PostgreSQL 16/17 Bytes / Espacio Rango / Especificación Recomendación de Arquitectura
Enteros INTEGER / BIGINT 4 B / 8 B -2.14B a +2.14B / ±9.22×1018 Usar BIGINT para llaves primarias con alto volumen transaccional.
Punto Fijo NUMERIC(p,s) Variable Hasta 131,072 dígitos antes y después del punto Obligatorio para dinero y contabilidad. Evita los errores de redondeo IEEE 754 de FLOAT.
Texto VARCHAR(n) / TEXT 1B + longitud Hasta 1 GB (almacenamiento TOAST) En PostgreSQL, TEXT y VARCHAR tienen idéntico rendimiento interno.
Temporal TIMESTAMPTZ 8 Bytes Fecha y hora con Zona Horaria (UTC) Estándar corporativo obligatorio para auditorías globales y logs distribuidos.
Identificador UUID 16 Bytes 128-bit universales (gen_random_uuid()) Ideal para microservicios y sistemas distribuidos offline-first.
Semiestructurado / IA JSONB / VECTOR(dim) Variable Binario indexable GIN / Embeddings HNSW Documentos polimórficos y búsqueda de similitud semántica con pgvector (2026).

04. Sintaxis Exhaustiva del Lenguaje DDL (Data Definition Language)

El lenguaje DDL permite definir, modificar y destruir esquemas y objetos de la base de datos.

Ejemplo Integral de DDL Profesional con Constraints Nombrados
-- 1. CREACIÓN DE EXTENSIÓN Y SCHEMA
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE SCHEMA IF NOT EXISTS ventas;

-- 2. CREACIÓN DE TABLA PADRE: CLIENTE
CREATE TABLE ventas.cliente (
    id_cliente          INTEGER GENERATED ALWAYS AS IDENTITY,
    codigo_uuid         UUID DEFAULT gen_random_uuid() NOT NULL,
    nombre              VARCHAR(50) NOT NULL,
    apellido            VARCHAR(50) NOT NULL,
    tipo_cliente        CHAR(1) DEFAULT 'R' NOT NULL,
    telefono            VARCHAR(15),
    email               VARCHAR(100) NOT NULL,
    credito_limite      NUMERIC(12,2) DEFAULT 0.00 NOT NULL,
    created_at          TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP NOT NULL,
    
    -- Restricciones de Tabla Nombradas
    CONSTRAINT pk_cliente PRIMARY KEY (id_cliente),
    CONSTRAINT uq_cliente_email UNIQUE (email),
    CONSTRAINT uq_cliente_uuid UNIQUE (codigo_uuid),
    CONSTRAINT chk_cliente_tipo CHECK (tipo_cliente IN ('R', 'VIP', 'CORP')),
    CONSTRAINT chk_cliente_credito CHECK (credito_limite >= 0.00)
);

-- 3. CREACIÓN DE TABLA HIJA: ORDEN_PEDIDO
CREATE TABLE ventas.orden_pedido (
    numero_orden        BIGINT GENERATED ALWAYS AS IDENTITY,
    id_cliente          INTEGER NOT NULL,
    fecha_colocacion    DATE DEFAULT CURRENT_DATE NOT NULL,
    fecha_entrega_est   DATE,
    numero_embarques    SMALLINT DEFAULT 1 NOT NULL,
    estado              VARCHAR(20) DEFAULT 'PENDIENTE' NOT NULL,
    monto_total         NUMERIC(12,2) DEFAULT 0.00 NOT NULL,
    
    -- Restricciones
    CONSTRAINT pk_orden_pedido PRIMARY KEY (numero_orden),
    CONSTRAINT fk_orden_cliente FOREIGN KEY (id_cliente)
        REFERENCES ventas.cliente (id_cliente)
        ON UPDATE CASCADE
        ON DELETE RESTRICT,
    CONSTRAINT chk_orden_embarques CHECK (numero_embarques > 0),
    CONSTRAINT chk_orden_fechas CHECK (fecha_entrega_est >= fecha_colocacion)
);

-- 4. MODIFICACIONES DE ESQUEMA MEDIANTE ALTER TABLE
-- Añadir columna de auditoría
ALTER TABLE ventas.orden_pedido ADD COLUMN observacion TEXT;

-- Modificar tipo de dato de una columna
ALTER TABLE ventas.cliente ALTER COLUMN telefono TYPE VARCHAR(25);

-- Añadir restricción CHECK posterior
ALTER TABLE ventas.orden_pedido ADD CONSTRAINT chk_orden_monto CHECK (monto_total >= 0.00);

-- Eliminar columna no requerida de forma segura
ALTER TABLE ventas.orden_pedido DROP COLUMN observacion;

-- 5. CREACIÓN DE ÍNDICES PROFESIONALES
CREATE INDEX idx_orden_cliente ON ventas.orden_pedido (id_cliente);
CREATE INDEX idx_cliente_email_lower ON ventas.cliente (LOWER(email));

Script DDL PostgreSQL 16/17 Completo y Ejecutable
-- Tabla 1: Línea de Producto
CREATE TABLE linea_producto (
    nombre_linea    VARCHAR(30) PRIMARY KEY,
    meta_venta      NUMERIC(12,2) NOT NULL CHECK (meta_venta >= 0.00)
);

-- Tabla 2: Producto
CREATE TABLE producto (
    id_producto     INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre_linea    VARCHAR(30) NOT NULL REFERENCES linea_producto (nombre_linea) ON UPDATE CASCADE,
    descripcion     VARCHAR(100) NOT NULL,
    stock           INTEGER DEFAULT 0 NOT NULL CHECK (stock >= 0),
    precio          NUMERIC(10,2) NOT NULL CHECK (precio > 0.00),
    costo           NUMERIC(10,2) NOT NULL CHECK (costo >= 0.00)
);

-- Tabla 3: Cliente
CREATE TABLE cliente (
    id_cliente      INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nombre          VARCHAR(60) NOT NULL,
    direccion       VARCHAR(120) NOT NULL,
    tipo            CHAR(1) DEFAULT 'A' NOT NULL CHECK (tipo IN ('A', 'B', 'C')),
    zip             VARCHAR(10) NOT NULL
);

-- Tabla 4: Orden de Pedido
CREATE TABLE orden_pedido (
    numero_orden        BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    id_cliente          INTEGER NOT NULL REFERENCES cliente (id_cliente) ON UPDATE CASCADE ON DELETE RESTRICT,
    fecha_colocacion    DATE DEFAULT CURRENT_DATE NOT NULL,
    fecha_llenado       DATE,
    numero_embarques    SMALLINT DEFAULT 1 NOT NULL CHECK (numero_embarques > 0)
);

-- Tabla 5: Producto Ordenado (Detalle de Pedido - PK Compuesta)
CREATE TABLE producto_ordenado (
    numero_orden        BIGINT NOT NULL REFERENCES orden_pedido (numero_orden) ON DELETE CASCADE,
    id_producto         INTEGER NOT NULL REFERENCES producto (id_producto) ON DELETE RESTRICT,
    cantidad_ordenada   INTEGER NOT NULL CHECK (cantidad_ordenada > 0),
    precio_unitario     NUMERIC(10,2) NOT NULL CHECK (precio_unitario > 0.00),
    PRIMARY KEY (numero_orden, id_producto)
);

-- Tabla 6: Factura (Relación 1:1 con Orden)
CREATE TABLE factura (
    numero_factura      BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    numero_orden        BIGINT NOT NULL UNIQUE REFERENCES orden_pedido (numero_orden) ON DELETE RESTRICT,
    fecha               DATE DEFAULT CURRENT_DATE NOT NULL,
    total               NUMERIC(12,2) NOT NULL CHECK (total >= 0.00)
);

-- Tabla 7: Pago
CREATE TABLE pago (
    id_pago             BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    numero_factura      BIGINT NOT NULL REFERENCES factura (numero_factura) ON DELETE CASCADE,
    fecha_pago          DATE DEFAULT CURRENT_DATE NOT NULL,
    monto               NUMERIC(12,2) NOT NULL CHECK (monto > 0.00)
);

-- Tabla 8: Centro de Trabajo
CREATE TABLE centro_trabajo (
    cod_ct          VARCHAR(10) PRIMARY KEY,
    nombre          VARCHAR(50) NOT NULL,
    ubicacion       VARCHAR(100) NOT NULL
);

-- Tabla 9: Empleado
CREATE TABLE empleado (
    cod_emp         INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    cod_ct          VARCHAR(10) NOT NULL REFERENCES centro_trabajo (cod_ct) ON UPDATE CASCADE,
    nombre          VARCHAR(80) NOT NULL,
    especialidad    VARCHAR(50) NOT NULL,
    direccion       VARCHAR(120),
    sueldo          NUMERIC(10,2) NOT NULL CHECK (sueldo > 0.00)
);

-- Tabla 10: Maquinaria
CREATE TABLE maquinaria (
    cod_maquina     VARCHAR(15) PRIMARY KEY,
    cod_ct          VARCHAR(10) NOT NULL REFERENCES centro_trabajo (cod_ct) ON UPDATE CASCADE,
    nombre_maq      VARCHAR(50) NOT NULL,
    ubicacion_maq   VARCHAR(80),
    tipo            VARCHAR(30) NOT NULL
);

-- Tabla 11: Orden de Trabajo (OT)
CREATE TABLE orden_trabajo (
    numero_ot       BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    numero_orden    BIGINT NOT NULL REFERENCES orden_pedido (numero_orden) ON DELETE CASCADE,
    fecha_inicio    DATE DEFAULT CURRENT_DATE NOT NULL,
    fecha_fin       DATE
);

-- Tabla 12: Asignación de Trabajo
CREATE TABLE asignacion_trabajo (
    numero_ot       BIGINT NOT NULL REFERENCES orden_trabajo (numero_ot) ON DELETE CASCADE,
    cod_ct          VARCHAR(10) NOT NULL REFERENCES centro_trabajo (cod_ct) ON DELETE RESTRICT,
    PRIMARY KEY (numero_ot, cod_ct)
);

-- Tabla 13: Materia Prima
CREATE TABLE materia_prima (
    cod_materia_prima   VARCHAR(15) PRIMARY KEY,
    nombre_mat_prima    VARCHAR(60) NOT NULL,
    cantidad            NUMERIC(10,2) DEFAULT 0.00 NOT NULL CHECK (cantidad >= 0.00),
    ubicacion           VARCHAR(80) NOT NULL
);

-- Tabla 14: Línea de Orden de Trabajo (Consumo de Insumos)
CREATE TABLE linea_orden_trabajo (
    id_producto         INTEGER NOT NULL REFERENCES producto (id_producto) ON DELETE RESTRICT,
    numero_ot           BIGINT NOT NULL REFERENCES orden_trabajo (numero_ot) ON DELETE CASCADE,
    cod_materia_prima   VARCHAR(15) NOT NULL REFERENCES materia_prima (cod_materia_prima) ON DELETE RESTRICT,
    cantidad_usada      NUMERIC(10,2) NOT NULL CHECK (cantidad_usada > 0.00),
    PRIMARY KEY (id_producto, numero_ot, cod_materia_prima)
);

💡 Tips del Profesor y Preguntas Clave de Examen

•
Nombre Explícito a cada Constraint: Nunca use constraints anónimos en producción. Si omite el nombre, el motor generará nombres autogenerados como cliente_tipo_check1, haciendo imposible alterar o depurar la restricción en migraciones automatizadas.
•
El Peligro de ON DELETE CASCADE Descontrolado: Si define ON DELETE CASCADE en la relación entre Clientes y Facturas, borrar accidentalmente un cliente eliminará todas sus facturas históricas, destruyendo los registros de auditoría contable y violando normas tributarias. En entidades financieras y de facturación, use siempre RESTRICT.
