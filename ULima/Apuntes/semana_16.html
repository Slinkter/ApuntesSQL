🚫 Top 5 Errores Fatales que Quitan Puntos

  • ❌ NOT IN con subconsulta con NULLs: Retorna siempre 0 filas. Usa NOT EXISTS.
  • ❌ Mutating Table en Triggers: Modificar la misma tabla en un trigger FOR EACH ROW.
  • ❌ Granularidad Duplicada en Hechos: Mezclar cabecera con detalle sin Surrogate Keys.
  • ❌ Olvidar COMMIT/ROLLBACK en Procedures: No controlar los límites transaccionales.
  • ❌ División Entera en Métricas: 5 / 2 = 2 en SQL. Usa 5.0 / 2 o CAST.

Banco de Preguntas Trampa de Alto Nivel Desglosadas

Pregunta 1 • Subconsultas y NULLs Trampa Clásica

¿Qué resultado arroja la consulta SELECT * FROM clientes WHERE cliente_id NOT IN (SELECT cliente_id FROM pedidos); si existe al menos un registro en pedidos cuyo cliente_id sea NULL?

Respuesta Correcta: Cero filas (Conjunto vacío).

Explicación Profunda: En SQL tri-valuado (True, False, Unknown), x NOT IN (1, 2, NULL) se evalúa como (x <> 1) AND (x <> 2) AND (x <> NULL). Como cualquier comparación con NULL resulta en UNKNOWN, toda la conjunción AND evalúa a UNKNOWN/FALSE, descartando todas las filas.

Solución recomendada para el examen: Usar siempre WHERE NOT EXISTS (SELECT 1 FROM pedidos p WHERE p.cliente_id = c.cliente_id).

Pregunta 2 • Modelado Dimensional Kimball Arquitectura OLAP

En un Data Warehouse, un cliente cambia de dirección residencial el 15 de marzo de 2026. Si el negocio requiere analizar las compras históricas hechas en su dirección antigua y las compras nuevas en su dirección actual, ¿qué técnica de Slowly Changing Dimension (SCD) se DEBE implementar?

Respuesta Correcta: SCD Tipo 2 (Creación de nueva fila con Surrogate Key y rango de vigencia).

Explicación Profunda: SCD Tipo 1 sobrescribe la dirección y alteraría las ventas del pasado. SCD Tipo 3 solo almacena la dirección previa en una columna pero no particiona los hechos por tiempo. Solo SCD Tipo 2 mantiene registros separados con diferentes Surrogate Keys (cliente_sk), permitiendo que los hechos antiguos apunten a la versión histórica y los nuevos a la actual.

Caso Práctico 1: Triggers de Validación, Auditoría Delta y Stored Procedure

Solución Completa Nota 20: Stored Procedure con Transacción y Trigger BEFORE PostgreSQL 16/17 
-- 1. Trigger BEFORE para validar invariantes de negocio y sanitizar
CREATE OR REPLACE FUNCTION fn_validar_transaccion_pago()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.monto <= 0 THEN
        RAISE EXCEPTION 'Error: El monto de pago debe ser estrictamente positivo (%)', NEW.monto;
    END IF;

    -- Sanitización automática en memoria antes del disco
    NEW.descripcion := TRIM(UPPER(NEW.descripcion));
    NEW.fecha_creacion := COALESCE(NEW.fecha_creacion, CLOCK_TIMESTAMP());
    
    RETURN NEW;
END;
$$;

CREATE OR REPLACE TRIGGER tr_valida_pago_before
BEFORE INSERT OR UPDATE ON pagos
FOR EACH ROW EXECUTE FUNCTION fn_validar_transaccion_pago();

-- 2. Procedimiento Almacenado con Control Transaccional Autónomo
CREATE OR REPLACE PROCEDURE sp_procesar_pago_orden(
    p_orden_id BIGINT,
    p_monto NUMERIC(12,2),
    p_metodo VARCHAR(32)
)
LANGUAGE plpgsql
AS $$
DECLARE
    v_total_orden NUMERIC(12,2);
    v_pagado_actual NUMERIC(12,2);
BEGIN
    -- Bloqueo pesimista de la orden
    SELECT total, monto_pagado 
    INTO v_total_orden, v_pagado_actual
    FROM ordenes
    WHERE orden_id = p_orden_id
    FOR UPDATE;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'La orden % no existe.', p_orden_id;
    END IF;

    IF (v_pagado_actual + p_monto) > v_total_orden THEN
        RAISE EXCEPTION 'Sobrepago no permitido. Total: %, Ya pagado: %', v_total_orden, v_pagado_actual;
    END IF;

    INSERT INTO pagos (orden_id, monto, metodo_pago, estado)
    VALUES (p_orden_id, p_monto, p_metodo, 'CONFIRMADO');

    UPDATE ordenes 
    SET monto_pagado = monto_pagado + p_monto,
        estado = CASE WHEN (monto_pagado + p_monto) = total THEN 'PAGADA' ELSE 'PARCIAL' END
    WHERE orden_id = p_orden_id;

    COMMIT;
END;
$$;

Caso Práctico 2: Star Schema Kimball y Consultas OLAP

Diseño DDL y Consulta Multidimensional CUBE PostgreSQL / Redshift / Snowflake 
-- 1. Dimensión SCD Tipo 2
CREATE TABLE dim_cliente (
    cliente_sk BIGSERIAL PRIMARY KEY,
    cliente_id INT NOT NULL,           -- Natural Key
    nombre_completo VARCHAR(150),
    segmento VARCHAR(50),
    region VARCHAR(50),
    fecha_inicio_validez DATE NOT NULL,
    fecha_fin_validez DATE,
    es_actual BOOLEAN NOT NULL DEFAULT TRUE
);

-- 2. Fact Table Transaccional con Métricas Aditivas
CREATE TABLE fact_ventas (
    venta_id BIGSERIAL PRIMARY KEY,
    fecha_sk INT NOT NULL,
    cliente_sk BIGINT REFERENCES dim_cliente(cliente_sk),
    producto_sk INT NOT NULL,
    tienda_sk INT NOT NULL,
    ticket_operacional VARCHAR(32),    -- Degenerate Dimension
    cantidad INT NOT NULL,
    monto_bruto NUMERIC(12,2) NOT NULL,
    descuento NUMERIC(12,2) NOT NULL,
    monto_neto NUMERIC(12,2) NOT NULL
);

-- 3. Consulta OLAP con Cubo Multidimensional Completo
SELECT 
    c.segmento,
    c.region,
    SUM(f.monto_neto) AS total_ventas,
    COUNT(DISTINCT f.ticket_operacional) AS total_tickets
FROM fact_ventas f
JOIN dim_cliente c ON f.cliente_sk = c.cliente_sk
GROUP BY CUBE (c.segmento, c.region)
ORDER BY c.segmento NULLS LAST, c.region NULLS LAST;
