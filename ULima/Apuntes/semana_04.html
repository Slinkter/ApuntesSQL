01. Fundamentos: Álgebra Relacional vs SQL Declarativo

El lenguaje SQL es declarativo: el desarrollador especifica qué resultados desea obtener, delegando al optimizador de consultas (Query Optimizer) la decisión procedimental de cómo acceder físicamente a los datos en disco o memoria.

Operación Formal Símbolo Matemático Sintaxis Equivalente SQL Semántica Operativa
Selección σcondición(R) SELECT * FROM R WHERE condición; Filtro horizontal: extrae las tuplas que satisfacen el predicado booleano.
Proyección πA1, A2(R) SELECT DISTINCT A1, A2 FROM R; Filtro vertical: extrae únicamente las columnas solicitadas y elimina duplicados.
Producto Cartesiano R × S SELECT * FROM R CROSS JOIN S; Combina cada tupla de $R$ con todas las tuplas de $S$ ($|R| imes |S|$ tuplas).
Reunión / Join R ⋈cond S SELECT * FROM R INNER JOIN S ON cond; Producto cartesiano seguido inmediatamente de una selección por coincidencia de claves.

02. Inserción Exhaustiva de Datos (INSERT)

La sentencia INSERT añade nuevas tuplas a una tabla. En entornos de producción, la inserción debe realizarse siempre especificando la lista explícita de columnas destino para garantizar la resiliencia del software ante futuros cambios de esquema.

Patrones Profesionales de Inserción SQL en PostgreSQL 17
-- 1. INSERCIÓN SIMPLE CON LISTA EXPLÍCITA DE COLUMNAS
INSERT INTO cliente (nombre, direccion, tipo, zip)
VALUES ('PEDRO CASTILLO', 'Av. Javier Prado Este 4600', 'A', 'L33');

-- 2. INSERCIÓN MULTI-FILA MASIVA (Batch Insert de Alto Rendimiento)
INSERT INTO linea_producto (nombre_linea, meta_venta) VALUES
('ESCRITORIOS', 150000.00),
('SILLAS ERGONOMICAS', 85000.00),
('ESTANTES MODULARES', 120000.00);

-- 3. INSERCIÓN BASADA EN CONSULTA (INSERT INTO ... SELECT)
INSERT INTO auditoria_clientes (id_cliente, nombre, fecha_registro)
SELECT id_cliente, nombre, CURRENT_TIMESTAMP
FROM cliente
WHERE tipo = 'A';

-- 4. PATRÓN MODERNO UPSERT: ON CONFLICT DO UPDATE (PostgreSQL 16/17)
INSERT INTO producto (id_producto, nombre_linea, descripcion, stock, precio, costo)
VALUES (101, 'ESCRITORIOS', 'Escritorio Roble Ejecutivo', 15, 850.00, 420.00)
ON CONFLICT (id_producto) 
DO UPDATE SET 
    stock = producto.stock + EXCLUDED.stock,
    precio = EXCLUDED.precio;

-- 5. INSERCIÓN CON CLÁUSULA RETURNING (Retorna el ID generado sin un SELECT adicional)
INSERT INTO orden_pedido (id_cliente, fecha_colocacion, numero_embarques)
VALUES (1, CURRENT_DATE, 2)
RETURNING numero_orden, fecha_colocacion;

03. Actualización de Datos (UPDATE) y Protocolos de Seguridad

La sentencia UPDATE modifica los valores de los atributos en tuplas existentes.

⚠️ La Regla de Oro del UPDATE en Producción

Si se ejecuta un UPDATE sin la cláusula WHERE, el motor actualizará todas las filas de la tabla de forma indiscriminada. En consolas de producción, siempre abra una transacción explícita con BEGIN;, verifique el número de filas afectadas y use ROLLBACK; si no coincide con lo esperado.

Ejemplos de Sentencias UPDATE Avanzadas
-- 1. ACTUALIZACIÓN CONDICIONAL SIMPLE
UPDATE orden_pedido
SET numero_embarques = 3,
    fecha_llenado = '2026-08-30'
WHERE numero_orden = 555;

-- 2. ACTUALIZACIÓN CON EXPRESIONES ARITMÉTICAS
-- Incrementar el precio en 8% para todos los productos de la línea 'ESCRITORIOS'
UPDATE producto
SET precio = ROUND(precio * 1.08, 2)
WHERE nombre_linea = 'ESCRITORIOS';

-- 3. ACTUALIZACIÓN BASADA EN JOIN (UPDATE ... FROM)
-- Actualizar el sueldo de los empleados del centro de trabajo 'CENTRO_SUR'
UPDATE empleado e
SET sueldo = sueldo * 1.12
FROM centro_trabajo ct
WHERE e.cod_ct = ct.cod_ct
  AND ct.ubicacion = 'LIMA SUR';

04. Análisis Comparativo Crítico: DELETE vs TRUNCATE

Aunque ambas operaciones vacían o eliminan datos de una tabla, su comportamiento interno en el motor DBMS es fundamentalmente distinto.

Criterio Técnico DELETE FROM tabla TRUNCATE TABLE tabla
Categoría SQL DML (Data Manipulation) DDL (Data Definition)
Granularidad y Filtro Admite cláusula WHERE para borrar filas específicas. No admite WHERE; vacía toda la tabla.
Mecanismo Interno Recorre y marca tuplas como muertas fila por fila (MVCC). Desasigna páginas de disco a nivel de filesystem de forma instantánea.
Generación de WAL / Logs Registra cada fila eliminada (alto volumen de WAL). Mínimo log WAL (solo el evento de desasignación de bloque).
Triggers Dispara triggers BEFORE / AFTER DELETE FOR EACH ROW. No dispara triggers por fila (solo triggers a nivel de sentencia).
Secuencias Auto-Increment Preserva el contador de la secuencia. Permite reiniciar secuencias con RESTART IDENTITY.
Rendimiento (10M tuplas) Lento (minutos u horas; genera hinchazón / bloat). Instantáneo (milisegundos).

05. Consultas SELECT y la Lógica Trivalente (3VL) con Valores NULL

El valor NULL representa ausencia de valor, dato desconocido o no aplicable. No equivale a cero ni a una cadena vacía. Por esta razón, el estándar SQL implementa la Lógica Trivalente (Three-Valued Logic - 3VL) con tres estados booleanos: TRUE, FALSE y UNKNOWN.

Tablas de Verdad de la Lógica Trivalente (3VL) en SQL
┌──────────────┬──────────────┬──────────────┐  ┌──────────────┬──────────────┬──────────────┐
│  A   AND   B │    RESULT    │  A   OR    B │  │  A   AND   B │    RESULT    │  A   OR    B │
├──────────────┼──────────────┼──────────────┤  ├──────────────┼──────────────┼──────────────┤
│ TRUE  AND TRUE     -> TRUE  │ TRUE  OR TRUE│  │ UNKNOWN AND TRUE   -> UNKNOWN│ UNKNOWN OR TR│ -> TRUE
│ TRUE  AND FALSE    -> FALSE │ TRUE  OR FALS│  │ UNKNOWN AND FALSE  -> FALSE  │ UNKNOWN OR FA│ -> UNKNOWN
│ TRUE  AND UNKNOWN  -> UNKNOWN│ TRUE  OR UNK │  │ UNKNOWN AND UNKNOWN-> UNKNOWN│ UNKNOWN OR UN│ -> UNKNOWN
└──────────────┴──────────────┴──────────────┘  └──────────────┴──────────────┴──────────────┘
                                ┌─────────────────────────────┐
                                │     NOT ( UNKNOWN ) -> UNKNOWN
                                └─────────────────────────────┘
  * REGLA CARDINAL DEL WHERE: Una fila SOLO se incluye si el predicado evalúa a TRUE.
    Si el resultado es FALSE o UNKNOWN, la fila se descarta.
Consultas SELECT con Operadores Avanzados
-- 1. CONSULTA CON PROYECCIÓN Y ELIMINACIÓN DE DUPLICADOS
SELECT DISTINCT tipo, zip
FROM cliente;

-- 2. TRATAMIENTO OBLIGATORIO DE VALORES NULL
-- Antipatrón: WHERE fecha_llenado = NULL;  (NUNCA retornará filas porque NULL = NULL es UNKNOWN)
-- Patrón Correcto:
SELECT numero_orden, id_cliente, fecha_colocacion
FROM orden_pedido
WHERE fecha_llenado IS NULL;

-- 3. FILTRADO CON RANGO (BETWEEN) Y CONJUNTOS (IN)
SELECT id_producto, descripcion, precio, stock
FROM producto
WHERE precio BETWEEN 100.00 AND 500.00
  AND nombre_linea IN ('ESCRITORIOS', 'SILLAS ERGONOMICAS');

-- 4. COINCIDENCIA DE PATRONES DE TEXTO (LIKE vs ILIKE)
-- ILIKE es insensible a mayúsculas/minúsculas en PostgreSQL
SELECT nombre, direccion, zip
FROM cliente
WHERE nombre ILIKE 'J%'            -- Comienza con J
  AND direccion LIKE '%Prado%';    -- Contiene 'Prado'

-- 5. EXPRESIONES CONDICIONALES CASE Y COALESCE
SELECT 
    numero_orden,
    fecha_colocacion,
    COALESCE(TO_CHAR(fecha_llenado, 'YYYY-MM-DD'), 'NO ATENDIDO') AS estado_entrega,
    CASE 
        WHEN numero_embarques > 3 THEN 'EMBARQUE MULTIPLE COMPLEJO'
        WHEN numero_embarques = 1 THEN 'EMBARQUE DIRECTO'
        ELSE 'EMBARQUE ESTANDAR'
    END AS categoria_embarque
FROM orden_pedido;

💡 Tips del Profesor y Preguntas Clave de Examen

•
La Trampa Clásica de WHERE con NULL: Pregunta fija de examen: "¿Qué filas devuelve la consulta: SELECT * FROM empleado WHERE sueldo < 3000 OR sueldo >= 3000?" Respuesta trampa: No devuelve todas las filas de la tabla. Si algún empleado tiene sueldo IS NULL, ambas comparaciones evalúan a UNKNOWN y UNKNOWN OR UNKNOWN es UNKNOWN, por lo que la fila queda excluida.
•
Orden de Ejecución vs Sintaxis: Recuerde que la cláusula WHERE se evalúa antes que el SELECT. Por ello, es un error de sintaxis intentar filtrar por un alias definido en el SELECT (e.g. SELECT precio * 1.18 AS precio_igv ... WHERE precio_igv > 100 fallará).
