\chapter{Normalizaci\'on Formal de Bases de Datos (1FN a 3FN) y Anomal\'ias}
\label{cap:normalizacion_1fn_3fn}

\section{Marco Conceptual y Te\'orico (Curr\'iculo Universitario)}

La normalizaci\'on es la t\'ecnica formal de dise\~no l\'ogico de bases de datos relacionales orientada a minimizar la redundancia y eliminar las anomal\'ias de actualizaci\'on, inserci\'on y borrado.

\subsection{Dependencias Funcionales}
Dado un esquema $R$, un conjunto de atributos $Y$ depende funcionalmente de $X$ ($X \rightarrow Y$) si y solo si cada valor de $X$ en $R$ se asocia con exactamente un \'unico valor de $Y$.

\subsection{Las Tres Formas Normales Cl\'asicas}
\begin{enumerate}
    \item \textbf{Primera Forma Normal (1FN):} Todos los atributos deben contener \'unicamente valores at\'omicos e indivisibles (sin grupos repetitivos ni arrays no normalizados).
    \item \textbf{Segunda Forma Normal (2FN):} Cumple la 1FN y ning\'un atributo no primo depende parcialmente de una clave candidata compuesta (eliminaci\'on de dependencia funcional parcial).
    \item \textbf{Tercera Forma Normal (3FN):} Cumple la 2FN y ning\'un atributo no primo depende transitivamente de la clave primaria ($X \rightarrow Y \rightarrow Z$).
\end{enumerate}

\section{Casos de Estudio y Descomposici\'on sin P\'erdida}

\begin{businessproblem}
Se dispone de un formulario desnormalizado de \'ordenes de venta donde los datos del cliente, transportista y detalle del producto residen en una sola estructura, generando duplicidad de registros cada vez que un cliente realiza un nuevo pedido.
\end{businessproblem}

\subsection{Descomposici\'on Formal en 3FN}

\begin{lstlisting}[style=sqlstyle, caption={Estructuras normalizadas en 3FN}]
-- 1. Tabla de Clientes (Elimina dependencia transitiva)
CREATE TABLE customers (
    customer_id BPCHAR(5) PRIMARY KEY,
    company_name VARCHAR(40) NOT NULL,
    contact_name VARCHAR(30),
    country VARCHAR(15)
);

-- 2. Tabla de \'ordenes (Depende directamente del cliente)
CREATE TABLE orders (
    order_id SMALLINT PRIMARY KEY,
    customer_id BPCHAR(5) NOT NULL REFERENCES customers(customer_id),
    order_date DATE NOT NULL,
    freight REAL DEFAULT 0.0
);

-- 3. Tabla de Productos (Independiente del pedido)
CREATE TABLE products (
    product_id SMALLINT PRIMARY KEY,
    product_name VARCHAR(40) NOT NULL,
    unit_price REAL NOT NULL
);

-- 4. Detalle de \'ordenes (Relaci\'on N:M normalizada)
CREATE TABLE order_details (
    order_id SMALLINT NOT NULL REFERENCES orders(order_id),
    product_id SMALLINT NOT NULL REFERENCES products(product_id),
    unit_price REAL NOT NULL,
    quantity SMALLINT NOT NULL,
    discount REAL DEFAULT 0.0,
    PRIMARY KEY (order_id, product_id)
);
\end{lstlisting}

\begin{engtip}
\begin{itemize}
    \item \textbf{Preservaci\'on de Dependencias:} La descomposici\'on garantiza que todas las restricciones de integridad y dependencias funcionales puedan verificarse localmente en cada tabla individual sin requerir uniones complejas antes de cada inserci\'on.
\end{itemize}
\end{engtip}
